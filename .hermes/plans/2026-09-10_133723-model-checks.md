# Deterministic Model Checks Implementation Plan

> **For Hermes:** Implement this plan task-by-task with strict TDD and independent review. Do not commit or push unless Marci explicitly requests it.

**Goal:** Add a compact, explainable model-checking panel that evaluates imported geometry against the active printer and settings, and highlights the exact affected model regions in the 3D viewport.

**Architecture:** Keep checks deterministic and local. A dedicated Web Worker receives each model's full `BufferGeometry` once, caches it by `fileId`, and recomputes transform/settings-dependent checks without blocking rendering. Reports contain metrics and triangle indices, while UI actions are mapped separately so analysis remains pure and testable.

**Tech Stack:** React 18, TypeScript, Three.js/R3F, existing `three-mesh-bvh`, Vitest, Web Workers.

---

## Scope and behavior

### Initial checks

1. **Build-volume fit**
   - Error when transformed geometry crosses X/Y/Z printer limits.
   - Report the offending axis and measured excess in millimetres.
   - Highlight the whole model with an out-of-bounds box/tint.

2. **Bed contact**
   - Warning when grounded geometry has only point/line contact or very little downward-facing area near Z=0.
   - Compare contact area with footprint and model height; avoid warning on ordinary broad flat bases.
   - Highlight contacting faces, not every low vertex.

3. **Mesh integrity**
   - Detect degenerate triangles, duplicate triangles, boundary edges/open shells, and edges owned by more than two faces.
   - Keep disconnected closed shells informational rather than automatically erroneous.
   - Highlight boundary/non-manifold neighborhoods where possible.
   - Reuse the same quantized vertex/edge rules as repair code to prevent contradictory results.

4. **Overhang estimate**
   - Transform face normals correctly for rotation, non-uniform scale, and mirrored axes.
   - Evaluate downward-facing area against the active `support_threshold_angle`.
   - Exclude bed-contact faces.
   - Explain that this is a geometric estimate, not OrcaSlicer's final support result.
   - Highlight only faces counted by the estimate.

5. **Nozzle-relative feature warning**
   - Use active `line_width`, falling back to nozzle diameter.
   - Build a BVH and conservatively sample inward ray distances between opposing surfaces.
   - Warn only when enough samples indicate thickness below the configured printable width; do not equate short triangle edges with thin printable features.
   - Show the estimated minimum/relevant thickness and configured reference width.
   - Label this result as an estimate because open meshes and complex internal cavities can produce false positives.

### Panel

- Compact overlay in the model viewport; collapsed summary by default after analysis.
- Header: `Model checks`, severity count, running indicator, collapse button.
- Group by selected model; scene selection shows aggregate findings.
- Each card contains severity, title, one-sentence reason, measured value, and one safe action.
- Clicking a card activates its viewport highlight. Clicking again clears it.
- Empty state: `No obvious geometry problems found`—never `Model is printable`.
- Checks do not block slicing in v1; build-volume errors continue to use existing placement behavior.

### Safe actions

- Build volume: `Center model` or `Select model`; no automatic scaling.
- Bed contact: `Choose base surface` (existing surface-placement workflow) or `Review brim`.
- Integrity: `Repair model` (existing repair operation), with the existing report shown afterward.
- Overhang: `Review supports`, opening Process settings filtered to support controls.
- Thin feature: `Review line width`, opening Process settings filtered to `line width`/`thin wall`.
- Every mutating action uses existing workspace history so Undo works.

## Task 4: Implement bed-contact and overhang checks

**Files:**
- Modify: `apps/web/src/features/slicer/lib/modelChecks.ts`
- Modify: `apps/web/src/features/slicer/lib/modelChecks.test.ts`

### Bed contact

1. Apply model rotation and scale to vertices.
2. Find transformed minimum Z.
3. Use a scale-aware tolerance (bounded in millimetres).
4. Count downward-facing triangles whose vertices lie at the grounded plane.
5. Compare contact area against XY footprint and model height.
6. Warn conservatively; point contact and tall/narrow models should warn, broad flat cubes should not.

### Overhang

1. Use inverse-transpose normal transformation and account for mirrored determinant sign.
2. Convert the configured support angle into one documented normal threshold.
3. Sum affected triangle area and percentage of total external area.
4. Exclude bed-contact triangles.
5. Return face indices for highlighting.

**Tests:** flat cube, tilted cube, mirrored scale, vertical wall, downward horizontal face, exact threshold boundary, bed-contact exclusion.

Use the existing `three-mesh-bvh` dependency. Build one BVH per geometry revision. Sample triangle centroids using deterministic area-stratified selection, cast inward rays, ignore the originating face and near-zero hits, and report a warning only when multiple neighboring samples agree.

**Guardrails:**
- Cap samples per model to bound runtime.
- Skip/mark unavailable for badly open or non-manifold meshes.
- Never infer thickness from tessellation edge length.
- Use `line_width` when finite and positive; otherwise use nozzle diameter.
- Report `estimate`, not `measured wall thickness`.

**Tests:** known parallel plates above/below threshold, closed cube, open plate, internal cavity, deterministic sampling, timeout/performance ceiling.

### Worker protocol

```ts
type RegisterGeometry = {
  type: 'register';
  fileId: string;
  revision: string;
  geometry: SerializedBufferGeometry;
};

type AnalyzeGeometry = {
  type: 'analyze';
  requestId: number;
  fileId: string;
  context: ModelCheckContext;
};

type RemoveGeometry = { type: 'remove'; fileId: string };
```

- Register once after `SlicerStlMesh` loads full, unoptimized geometry.
- Cache geometry/topology/BVH inside the worker.
- Reanalyze on rotation, scale, position, build volume, support threshold, nozzle diameter, or line width changes.
- Debounce transform changes and discard stale responses by `requestId`.
- Remove cached geometry when the model is removed.
- If Worker startup fails, return `failed` without blocking viewport or slicing; do not run expensive fallback synchronously.

## Recommended delivery slices

1. **MVP:** Panel + build-volume + integrity + highlights.
2. **Second slice:** Bed contact + overhang + setting links.
3. **Third slice:** BVH thickness estimate after measuring performance/false positives.
4. **Later experiment:** Optional semantic image model behind a feature flag; never required for deterministic checks and never used as proof of printability.

## Key risks and mitigations

- **False confidence:** Say `No obvious geometry problems found`, never `printable` or `safe`.
- **False-positive overhangs:** Describe as geometric estimate; Orca remains authoritative for support generation.
- **Bad thin-wall estimates:** Conservative multi-sample BVH result, skip invalid/open meshes, and label estimate.
- **UI stalls:** Worker caching, bounded sampling, debounce, stale-response cancellation.
- **Memory growth:** Explicit register/remove lifecycle and disposal tests.
- **Transform errors:** Shared transform utilities with mirrored/non-uniform-scale fixtures.
- **Scope growth:** No AI, cloud calls, auto-fixes, or automatic setting changes in v1.

## Open product decisions before implementation

- Whether the panel starts collapsed or expanded on the first warning. Recommended: collapsed when clean, expanded on the first error only.
- Whether modifier meshes receive checks. Recommended: exclude modifiers in v1 and say so internally; analyze printable roots only.
- Whether build-volume findings block Slice. Recommended: retain current behavior initially; do not change slicing semantics as part of this feature.
